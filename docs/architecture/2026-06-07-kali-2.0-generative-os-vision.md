# KALI 2.0 — Generative OS Vision & Reference Architecture

**Status:** North-Star vision (not current state). Date: 2026-06-07.
**Audience:** Founder, future contributors, investors.
**Purpose:** Lock the long-horizon vision and a *capability-elastic* reference
architecture for KALI's evolution from voice-first agent creator → generative OS.

> **Relationship to the other diagrams:** [`c4-context.md`](c4-context.md) and
> [`c4-containers.md`](c4-containers.md) describe KALI **today**. This document is
> where we are **going**. The technology inside the boxes will change as AI
> advances — the **vision, the moat, and the dials stay**.

---

## 1. Thesis & strategic context

**The shift:** today's operating systems (Windows, Linux, macOS, Android, iOS) are
**static** — the user adapts to a fixed system. The OS of the future is
**generative**: it composes backend logic, UI, functionality and security *per user,
per intent*, in real time. Iron-Man's JARVIS — but private and yours.

**Why not fight the giants head-on.** Every adjacent move on the market —
OpenAI's "superapp", Anthropic's Orbit, OpenHuman, OpenJarvis — converges on the
same stack: *agents + actions + memory + routing + OAuth integrations*. That is
already **table stakes** and the giants' home turf. A solo founder cannot out-spend
them there.

**Value-at-edges thesis.** As AI capability commoditizes, value migrates to the
**edges the giants cannot copy**:

- **Trust / privacy / data ownership** — local, yours. Becomes *more* important, not
  cheaper, as agents grow more autonomous and powerful.
- **Distribution** — the UGC loop (create-by-voice → share reel → friends install),
  RU-first, non-tech segment.
- **The human interface** — voice for non-technical people + the Jarvis persona.

**North-Star.** A **generative, local-first, safe** OS where a non-technical person
*speaks* and receives a personal system built for them. "Generative OS" is the
**ceiling of KALI's existing wedge** (voice-first creation for non-tech), not a new
game on the giants' field.

> **Naming note:** the "Jarvis" persona name and the Iron-Man metaphor are
> **provisional** in this document, pending the Marvel-IP licensing review flagged for
> public launch. The metaphor conveys the vision; the shipping persona name may differ.

## 2. Design principles (locked)

1. **Capability elasticity.** The architecture is a set of **dials on the AI curve**,
   not fixed bets. As models get stronger / smaller / cheaper / more reliable, the
   same containers exploit them by *sliding a dial*, not by rewriting.
2. **Reasoner = swappable commodity.** KALI is never bound to one model or provider.
   A single `reasoner` abstraction hides local vs cloud, today's model vs tomorrow's.
3. **Invest at the edges.** Keep the model layer thin and replaceable; invest
   *thickly* in the non-commoditizing layers: trust/local-data, the voice wedge,
   distribution.
4. **Safe generativity.** A declarative spine (`SKILL.md` / UI-schema / workflow-DSL)
   with **escalation to sandboxed code**; every generated thing is **validated before
   it runs** and then runs capability-bounded with **plain-language consent**.
   Generativity grows *more* dangerous as models improve → boundaries grow *more*
   important, not less.
5. **Local-first trajectory.** Hybrid-routed today (cloud for heavy work) → on-device
   as models shrink and dedicated hardware arrives. Cloud is *used*, never an
   ideological dependency.
6. **The ladder A → B → C.** Build the architecture for the whole path; ship by rungs.

## 3. Core decisions (the four locks)

| Dimension | Decision |
|---|---|
| **Ambition** | **D — ladder** A→B→C. North-Star = **C** (generative OS + hardware). |
| **Generation substrate** | **(iv) hybrid** — declarative `SKILL.md` spine + escalation to sandboxed code. |
| **Locality** | **(d) trajectory** — hybrid-routed now → local / on-device endgame. |
| **Trust model** | **(iv)** — capability-sandbox + curated blocks for dangerous actions + plain-language consent. |

**The ladder defined:**

- **A — Generative agents/mini-apps.** Voice → generated agents/workflows on a normal
  host OS. *(Direct continuation of the current wedge; fastest to revenue.)*
- **B — Generative shell.** The interface itself composes around the user's intent and
  context, then dissolves. *(The "Iron Man HUD"; lives on a host OS.)*
- **C — Generative OS + device.** The system layer itself (runtime, security,
  drivers-for-task) is AI-composed, optionally on dedicated hardware.

> A = *what's inside*, B = *how it looks and composes*, C = *what it all stands on*.

### How to read it

- **The generative loop:** voice → `core` turns intent into declarations (escalates to
  code when needed) → `router` gets reasoning (local/cloud) → `runtime` executes within
  bounds → `composer` decides what to show → `surface` renders. `memory` feeds context
  throughout; `consent` gates access in plain language.
- **Generated ≠ trusted.** `core` validates and dry-runs every generated artifact
  *before* install. The sandbox bounds *blast radius*; validation bounds *correctness* —
  essential for a non-tech user who cannot read the generated code. **This is the
  load-bearing seam of the whole product** (a plausible-but-wrong agent is the core
  failure mode), so it is modeled here, not left to implementation.
- **Cloud-TTS** (ElevenLabs — a separate external system at L1) is folded into the
  `Voice Gateway` note at this level: same fallback, internalized at the container view.
- **Moat vs commodity:** invest thickly in the **edges** — voice, memory/data,
  sandbox-trust, distribution. `router → reasoners` is the only **commodity seam**.
- **Distribution loop closes here too:** `user → dist → ugc → friends → dist (install)`,
  mirroring the L1 context loop.
- **Maturity map:** `[EXISTS]` voice/router/memory/surface-A + `[PARTIAL]`
  core/sandbox/catalog/consent/dist ⇒ **rung A is largely assemblable from what already
  exists.** `composer` is the one new container (rung B). Rung C lowers the
  sandbox + surface into the system layer + hardware.

## 6. The three dials (how future AI growth slots in without rework)

| Dial | Today | Slides to | Mechanism |
|---|---|---|---|
| **Reasoner locality** | cloud for heavy, local for light | local-first → on-device | `Reasoner Router` routing policy (config slide) |
| **Generation substrate** | declarations (safe) | + sandboxed code as code-gen reliability rises | **new capability** behind a reliability gate — adds a code-gen + validation/eval seam, *not* a free knob |
| **Surface** | A (chat + store) | B (generative shell) → C (device) | `UI Composer` + `Surface` |

This is where "everything could change in 1–2 years" is *absorbed by design*: we build
H1 on today's models; tomorrow the **same containers** use stronger models by sliding a
dial. **Caveat (honesty):** the *reasoner* and *surface* dials are genuine config
slides; the *substrate* dial's right-hand position (generating and running code) is a
**planned new capability** — it brings its own code-gen pipeline and validation/eval
seam, gated behind code-gen reliability. Planned for, not free.

## 7. Decomposition into buildable bets

Principle: each bet **ships value now** and **lays a seam** toward the North-Star.
Almost all of Horizon 1 is *finishing what already exists*.

### Horizon 1 — rung A (now): finish the wedge + lay the spines

| # | Bet | Ships | Builds on |
|---|---|---|---|
| 1 | **Voice → Agent generation** | non-tech speaks → KALI generates a `SKILL.md` agent → **validates / dry-runs** → installs → works. **Revenue + UGC.** | voice-builder (Gate B) |
| 2 | **Capability-trust spine** | agents safely *act* (files / calendar / messaging): sandbox + plain-language consent + catalog for dangerous actions | sandbox, permission_enforcer |
| 3 | **Reasoner seam + local** | `Reasoner Router` → a clean `reasoner` abstraction; pluggable local + cloud; dial toward local | llm_router |
| 4 | **Memory personalization** | "KALI remembers you": hierarchical local memory feeds generation (counter to OpenHuman) | LongTermMemory |
| 5 | **UGC loop** | share → install with no friction + reel hook | catalog / package |

> **Ordering constraint (safety):** Bet 2 (trust spine) is a hard prerequisite for the
> *acting* part of Bet 1. Bet 1 may ship **generation + validation/dry-run + read-only
> first**; any **write or external action** waits for Bet 2's capability-sandbox +
> consent. Principle 2.4 (capability-bounded + consent for *everything* generated) is
> non-negotiable, so generation-that-acts cannot precede the spine.
>
> **Open question (for the Bet 1 / Bet 3 specs): the H1 cloud-reasoning cost model.**
> The wedge routes generation through cloud reasoners at H1 (local is endgame). At UGC
> scale, per-generation token cost is a first-order business risk — decide BYO-key vs
> founder-subsidized vs per-user cap *before* the wedge ships broadly.

### Horizon 2 — rung B (next): generative shell

| # | Bet | Ships | Builds on |
|---|---|---|---|
| 6 | **UI Composer MVP** | the interface **assembles itself** around intent (a generated mini-workspace, not a fixed screen) | new container (the main new one) |

### Horizon 3 — rung C (seams, NOT built now)

Code-gen escalation (substrate dial fully right) · on-device inference · hardware
device · private multi-device sync. The architecture **supports** these via the dials;
we slide them as AI / hardware mature. The existing **Rust backend is already the
local-first / performance foundation** for this rung.

## 8. Reconciliation with binding rules

- **Anti-pivot rule intact (operationally testable).** Capability blocks may touch
  **personal-life services** (calendar, home, messengers, personal email); they may
  **not** target **developer/design workflows** — IDEs, CI/CD, cloud consoles, design
  tools. That is the checkable line, not just an assertion. The Capability Catalog and
  "life services" stay on the personal side. We do not step onto the giants' turf.
- **Current tracks feed the vision, don't conflict with it.** Premium v3 (shipped),
  Gate A Rust cutover, latency P2/P3, mobile — these are the **foundation**: Rust →
  locality/perf; latency → the voice-first UX the wedge depends on.
- **Commoditization is planned for.** The locality and surface dials slide without
  rewrites; the substrate's code-escalation is a *planned new capability* (see §6). We
  build H1 on today's models and ride the curve.

## 9. What this is NOT (scope guards)

- **Not a self-writing kernel.** Generativity is capability-bounded and sandboxed.
  "The OS writes its own production backend" means *declarations + sandboxed code within
  enforced limits, validated before they run* — not unrestricted code in the system.
- **Not cloud-dependent by ideology.** Cloud is a dial position, not a foundation.
- **Not a developer tool.** The non-tech voice wedge holds; developers remain a
  secondary, catalog-publishing persona.
