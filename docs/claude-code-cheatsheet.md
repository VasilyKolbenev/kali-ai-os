# Claude Code — шпаргалка возможностей

Личный справочник: что есть, когда применять, зачем для сложных проектов.
Состав скиллов/команд зависит от установленных плагинов — `/help` покажет
актуальный список в твоей сессии.

---

## 1. Режимы работы (фундамент потока)

| Режим | Как включить | Зачем |
|---|---|---|
| **Plan mode** | Shift+Tab (цикл режимов) или «составь план, не пиши код» | Claude исследует и предлагает план, НЕ трогая код. Утверждаешь → выполняет. Защита от «наговнокодил не то». |
| **Auto-accept / Accept edits** | Shift+Tab | Правки применяются без подтверждения каждой — быстрее в потоке, когда доверяешь. |
| **Default (ask)** | Shift+Tab | Спрашивает разрешение на действия. Безопасно для незнакомого репо. |
| **Fast mode** | `/fast` | Тот же Opus, но быстрее вывод. Для интерактивной работы. |

**Сложные проекты:** всегда начинай большую задачу с plan mode — согласовал
подход, добавил свои ограничения, потом запускаешь. Это «план-гейт».

## 2. Процессные скиллы (superpowers) — КАК работать

Это не про код, а про дисциплину. Самое ценное на сложных проектах и интервью.

| Скилл | Когда | Что даёт |
|---|---|---|
| **brainstorming** | Перед любой новой фичей | Раскапывает намерение и требования ДО кода. Не даёт строить не то. |
| **writing-plans** | Есть спека/требования | Пишет многошаговый план с точками верификации. |
| **executing-plans** | Есть готовый план | Выполняет план с чек-поинтами ревью. |
| **test-driven-development** | Любая фича/багфикс | Сначала падающий тест → потом код. Дисциплина уровня senior. |
| **systematic-debugging** | ЛЮБОЙ баг | 4 фазы: найти root cause → паттерн → гипотеза → фикс. Не «попробуем это». |
| **verification-before-completion** | Перед «готово» | Запусти команду, покажи вывод. Доказательство, не «вайбы». |
| **requesting-code-review** | Завершил фичу/перед мержем | Проверка работы против требований. |
| **receiving-code-review** | Получил фидбек | Технически проверяет правки, а не слепо соглашается. |
| **using-git-worktrees** | Изолированная фича | Отдельный worktree — работаешь, не ломая основной. |
| **subagent-driven-development** | План с независимыми задачами | Выполняет задачи плана субагентами в текущей сессии. |
| **dispatching-parallel-agents** | 2+ независимых задач | Параллельный запуск без общего состояния. |

**Вызов:** просто опиши задачу — Claude сам подхватит нужный скилл. Или явно:
«используй systematic-debugging».

## 3. Слэш-команды (быстрые действия)

Набор зависит от плагинов. Частые:

- **/plan** — спланировать реализацию.
- **/review** — ревью кода/PR.
- **/code-review** — ревью текущего диффа (low/medium/high/**ultra** = облачный мульти-агент). `--fix` применяет, `--comment` пишет в PR.
- **/security-review** — security-аудит изменений.
- **/test** — прогнать/написать тесты.
- **/refactor** — рефакторинг.
- **/explain** — объяснить код/изменения.
- **/commit** (commit-work) — аккуратные атомарные коммиты с хорошими сообщениями.
- **/status**, **/save** — статус сессии, сохранить состояние.
- **/loop** — запустить промпт/команду на повторе по интервалу.
- **/init** — сгенерировать CLAUDE.md под проект.

**Сложные проекты:** `/code-review ultra` перед мержем крупной ветки —
многоагентное облачное ревью находит то, что один проход пропускает.

## 4. Субагенты и параллелизм — масштаб одной сессии

| Инструмент | Зачем | Когда для сложного |
|---|---|---|
| **Explore** (агент) | Read-only поиск по репо, читает выдержки | «Где реализован X?», «все места, где Y» в большой кодбазе — не читаешь файлы руками |
| **Plan** (агент) | Проектирует план реализации | Архитектурные решения, трейд-оффы |
| **general-purpose** | Многошаговое исследование/задачи | Когда не уверен, что найдёшь с первого раза |
| **code-reviewer / code-simplifier** | Спец-ревью после куска кода | Качество перед коммитом |
| **Task-инструменты** (фоновые) | Длинные команды в фоне | Сборки, тесты — не блокируют диалог |

**Ключевое:** субагент возвращает ВЫВОД, не засоряя твой контекст файлами.
На большом репо это спасает контекст. Запускай несколько НЕзависимых — в одном
сообщении (идут параллельно).

## 5. Workflow — детерминированная мульти-агентная оркестрация

Скрипт, который раскладывает работу по десяткам агентов: fan-out (покрыть всё
параллельно), верификация (независимые проверки + адверсариальная защита),
масштаб (миграции, аудиты, широкие свипы).

- **Когда:** «прошерсти весь репо на баги», «мигрируй N файлов», «аудит
  безопасности по 6 зонам». Большой объём + нужна структура.
- **Паттерны:** find→dedup→verify, judge-panel (N подходов → оценка →
  синтез), loop-until-dry (ищем, пока не пусто), adversarial-verify (N
  скептиков на находку).
- **Осторожно:** дорого и долго (десятки агентов). На LIVE-интервью — НЕ
  тащить. Для реального большого аудита/миграции — самое то.

> Мы так делали pre-release аудит KALI (6 зон + адверсариальная проверка → 23
> фикса) и generator→validator на фиксах.

## 6. Память и контекст — между сессиями

| Механизм | Зачем |
|---|---|
| **CLAUDE.md** | Инструкции проекта, всегда в контексте. Конвенции, команды, архитектура. `/init` создаёт. |
| **memory/** (авто-память) | Факты, что переживают сессии: кто ты, договорённости, состояние проекта. Подтягивается автоматически. |
| **session-handoff** | Хэндофф-документ для бесшовной передачи следующей сессии (когда контекст полон или работа на паузе). |
| **/save, log-to-daily** | Сохранить состояние / записать в дневник. |
| **Авто-суммаризация** | Когда диалог длинный — контекст сжимается, работа продолжается. Не надо обрывать. |

**Сложные проекты:** это твой главный множитель. Хэндофф в конце сессии +
память → следующая сессия стартует с нуля контекста, но со всем знанием. Мы так
вели KALI неделями.

## 7. MCP-инструменты — внешний мир

| Сервер | Зачем |
|---|---|
| **context7** | Свежие доки библиотек/фреймворков/API. Вместо галлюцинаций — актуальный синтаксис. «Проверь через context7». |
| **preview** (preview_start/snapshot/screenshot/click…) | Запуск dev-сервера, скриншоты, клики — верификация UI глазами и пруфы. |
| **computer-use** | Управление десктопом (мышь/клава/скриншот) для нативных приложений и кросс-аппных сценариев. |
| **Claude-in-Chrome** | Управление браузером (DOM-aware), для веб-приложений. |
| **Другие** (Slack, GitHub, Jira, Figma…) | По мере подключения — прямые интеграции вместо ручной возни. |

**Совет:** перед работой с незнакомой библиотекой — context7. Для UI-фич —
preview со скриншотом как доказательство.

## 8. Отслеживание прогресса и верификация

- **TodoWrite / задачи** — список шагов на экране. На сложной задаче показывает
  структуру и прогресс (и тебе, и зрителю/ревьюеру).
- **/verify, /run** — запустить приложение и убедиться, что фича реально
  работает (не только тесты).
- **preview_*** — для previewable-изменений: запустил, кликнул, заскриншотил.

**Железное правило:** «готово» = показал доказательство (вывод теста, скриншот,
ответ API). Никогда не утверждай без запуска.

## 9. Git и изоляция

- **commit-work** (/commit) — ревью изменений, разбивка на логические коммиты,
  хорошие сообщения (Conventional Commits).
- **using-git-worktrees** — изолированная ветка в отдельной папке. Для
  параллельной/рискованной работы без риска основному дереву.
- **finishing-a-development-branch** — структурно завершить: мерж / PR / уборка.

**Сложные проекты:** worktree под крупную фичу = можешь экспериментировать и
откатиться, не трогая main. Субагенты-исполнители тоже работают в изолированных
worktree (в Workflow).

## 10. Доменные/спец-скиллы (по потребности)

Не учить наизусть — знать, что есть, и звать по имени:

- **Архитектура/диаграммы:** c4-architecture, mermaid-diagrams, excalidraw, draw-io.
- **Фронтенд:** frontend-design (нестандартный продакшн-UI), react-dev, react-useeffect, mui, design-system-starter.
- **Бэкенд/данные:** database-schema-designer, supabase, openapi-to-typescript.
- **Качество:** skill-judge, naming-analyzer, reducing-entropy (минимизация кода), lesson-learned.
- **Документация:** crafting-effective-readmes, writing-clearly-and-concisely, agent-md-refactor.
- **Продукт/коммуникация:** game-changing-features, requirements-clarity, professional-communication.
- **Внешние модели:** codex (GPT-5.2), gemini (большой контекст/ревью), perplexity (веб-поиск).
- **Исследование:** deep-research (мульти-источник, фактчек, цитаты).

## 11. Стратегия для СЛОЖНЫХ проектов (синтез)

1. **План-гейт** — большую задачу начинай с plan mode; добавь ограничения,
   критерии успеха, ключевые файлы, проверки. Потом запускай.
2. **Generator→Validator** — один агент делает, другой (независимый, скептичный)
   проверяет против реального кода. Ловит правдоподобную чушь.
3. **Декомпозиция через субагенты** — большой поиск/работа → fan-out Explore;
   контекст не засоряется.
4. **Память + хэндоффы** — состояние живёт между сессиями. Конец сессии =
   хэндофф + обновление памяти.
5. **Верификация = доказательство** — тесты + запуск приложения + скриншоты.
   Для голоса/UI — реальное воспроизведение, не «синтез прошёл».
6. **Worktree для риска** — экспериментируешь изолированно.
7. **Workflow для масштаба** — аудиты, миграции, широкие свипы (но не для
   мелочи — дорого).
8. **Атомарные коммиты** — один логический сдвиг = один коммит, понятное
   сообщение. Легко откатывать и ревьюить.

## 12. Памятка для LIVE vibecoding (отдельно)

**Ритм:** проговори задачу → план (если >пары шагов) → падающий тест/критерий →
код малыми кусками вслух → запусти и покажи → отрефлексируй угол среза.

**Сильные ходы на экране:** plan mode · TDD (красный→зелёный) ·
systematic-debugging на баге · Explore для навигации · context7 для незнакомого
API · верификация с выводом.

**Не делай:** молча кодить · «готово» без запуска · раздувать скоуп · залипать в
одном подходе >2 раз · тащить тяжёлый Workflow без запроса на масштаб.
