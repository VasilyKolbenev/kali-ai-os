## Session Log - 4:50 PM

**Focus:** TTS latency optimization — Qwen3-TTS с CPU на GPU (bfloat16), streaming по предложениям

### Completed
- Диагностировали что Qwen3-TTS-1.7B работала полностью на **CPU** (старый код пытался двигать на GPU неправильные атрибуты)
- Переписали `services/tts/server.py` — корректная загрузка: CPU → bfloat16 → CUDA (3.7GB VRAM)
- Добавили **streaming endpoint** `/synthesize/stream` (SSE, разбивка на предложения)
- Обновили **фронтенд** `ChatInput.tsx` — progressive audio playback через SSE queue
- Обновили **kernel** `/tts` proxy для streaming поддержки
- Выяснили что сервер надо запускать из conda env `kali-tts` (torch+CUDA), а не системным Python 3.14 (CPU-only)
- **Бенчмарк: 35с → 8с** (короткая фраза), **60с+ → 18с** (длинный ответ)

### Decisions Made
| Decision | Rationale |
|----------|-----------|
| bfloat16 вместо float32 | Вдвое меньше VRAM (3.7 vs 7.2GB), вписывается в 8GB RTX 5070 |
| Sentence-level streaming | Первый звук через 8-9с вместо ожидания всей генерации |
| SSE (Server-Sent Events) | Простая реализация, без WebSocket, совместимо с fetch API |
| Conda env kali-tts | Системный Python 3.14 имеет CPU-only torch, conda имеет CUDA 12.8 |
