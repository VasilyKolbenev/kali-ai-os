## Known gotchas (carry-forward)

All in `memory/feedback_ml_build_friction.md` + `memory/project_rust_migration.md`. Phase 4 added these:

1. **`source` field in thiserror enums conflicts with std::error::Error::source() derivation magic.** Rename to `src` (or use `#[source]` attribute) to avoid `as_dyn_error` trait-bound errors. Bit me in `CatalogFetchError`.
2. **Browser preview-verification is overkill for dispatcher allow-list changes.** Integration tests via mock servers cover the wire contract; UI components themselves don't change. Skip preview when integration test exercises the full path. Document the rationale in the commit message.
3. **Combined proxy contract test is the right pattern** when `KALI_PYTHON_BACKEND_URL` is involved. Splitting per-route races on the env var. One mock + one Rust + sequential calls.
4. **Option C (proxy) is a legitimate Rust-port outcome** when the Python source has security-critical logic (AST analysis, zip-extraction hardening) for a cold-path operation. Document in the commit message; Phase 8 retires the proxy.
5. **Skills validator's "unknown frontmatter keys" warning was dropped on the Rust side** because serde silently ignores unknowns during loader parse. Recreating it would mean parsing into `Value` first then re-deriving — extra moving part for a low-value advisory. Documented in `validator.rs` module comment.
